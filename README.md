# Portfolio Pulse AI

A standalone demo of "Portfolio Pulse AI" — an AI-generated briefing that
replaces a bare portfolio value with "everything that changed since your
last visit," built for FundsIndia as a product concept prototype.

There is no real FundsIndia integration here. Every fund, price, market
event, and transaction is generated by a deterministic seed script so the
demo has a believable, internally consistent story to walk through. The
data layer (`src/lib/data/repository.ts`) is the seam where a real
integration would slot in later.

## Setup

```bash
npm install
cp .env.local.example .env.local   # add your ANTHROPIC_API_KEY
npm run seed                        # generates src/lib/data/seeds/*.json
npm run dev
```

Open http://localhost:3000 — it redirects to `/dashboard`.

Without `ANTHROPIC_API_KEY` set, the app still works end-to-end: every
LLM-generated section (mover reasons, attribution explanations, jargon,
AI insights, opportunity nudges, concern narrative, and the "Ask AI" chat)
falls back to deterministic, template-based text built directly from the
same computed facts.

## Exploring the demo

The dashboard simulates a sequence of 8 "login sessions" spread across a
generated 90-day market history. Use the controls at the top of the page:

- **Simulate next login →** advances to the next session, showing the diff
  since the previous one.
- **Reset** returns to the first comparable session.
- A manual override is also supported via query params, e.g.
  `/dashboard?from=snap-01&to=snap-08` to compare any two sessions directly
  (useful for demoing a specific before/after without clicking through).

## Regenerating data

`scripts/generate-seed-data.ts` is the single source of truth for the fake
dataset. It's a deterministic, seeded script (not run at request time) —
editing the macro event timeline, fund roster, or transaction schedule and
re-running `npm run seed` regenerates all of `src/lib/data/seeds/*.json`
with a fresh, internally consistent story (market events drive index moves,
which drive fund NAVs, in that order).

## Architecture

- `src/lib/data/` — types, seed data, and `repository.ts` (the only module
  other code should import fund/snapshot/event data through).
- `src/lib/engines/` — deterministic, non-LLM logic: snapshot diffing,
  market attribution heuristics, relevant-event filtering, concern
  classification, and opportunity detection. These compute every number
  shown in the app.
- `src/lib/llm/` — the Claude integration. Engines hand off already-computed
  facts to Claude, which only turns them into prose — it never invents or
  recalculates a number. Falls back to `fallback.ts`'s deterministic prose
  if the API key is missing or the call fails.
- `src/components/` — one component per spec section (movers, attribution,
  jargon, allocation, events, insights, concern, opportunities, chat).
- `src/app/api/` — `snapshot-diff` (pure engine output), `briefing` (LLM
  prose, one combined call per dashboard load), `chat` (streaming, scoped
  to the current portfolio's data).
